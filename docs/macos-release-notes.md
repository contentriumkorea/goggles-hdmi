Apple Silicon macOS · 버전 1.2.5

**1.2.5는 Mac 외부 화면 픽셀 조회와 전체화면 상태 처리를 수정합니다.** Qt와 동일한 NSScreen 좌표 변환으로 화면을 식별한 뒤 실제 CGDisplayMode 픽셀을 조회합니다. 논리 좌표와 물리 픽셀을 직접 비교하던 매칭 실패를 수정했으며 조회 실패가 출력 창을 닫지는 않습니다. 출력 대상은 첫 표시 전에 지정하고, 출력 요청은 유지됐지만 네이티브 전체화면 상태만 풀린 경우 앱이 활성 상태이고 같은 대상 화면이 연결된 때에 한해 한 번 복원합니다. 다른 앱으로 전환했을 때는 복원하거나 포커스를 가져오지 않습니다. 출력 종료·Escape는 예약된 복원도 취소합니다. 자동 복원이 생략되거나 다시 풀리면 출력 복원 버튼으로 직접 복원할 수 있습니다.

문제 정보 복사에 Qt·네이티브 창의 표시/전체화면 상태, 대상·실제 화면의 순번, 논리 좌표·DPR·픽셀 조회 결과와 최근 출력 이벤트가 추가됩니다. 화면 이름·일련번호·기기 식별값은 제외합니다. 실제 Mac에서 전체화면이 풀린 최초 이벤트는 아직 확정되지 않았으므로 설치 후 유지 여부와 새 보고서로 확인해야 합니다. 1.2.4 사용자 보고서에서는 USB 한 세션·재연결 0회와 경계 복구 6회가 확인됐습니다. USB 경계 복구와 HTTPS 인증서 수정은 유지합니다.

**1.2.4는 실제 1.2.3 보고서에서 확인한 읽기 경계의 잔여 1바이트를 제한적으로 복구합니다.** 보고된 값 216·237·25가 다음 정상 RNDIS 헤더 앞에 붙어 발생한 오류를 그대로 재현했습니다. 이미 정상 메시지를 받은 연결에서, 이전 읽기에 남은 바이트가 정확히 하나이고 정상 헤더의 첫 바이트 1이나 0이 아니며, 새 읽기 전체가 시작 위치부터 완전한 RNDIS 메시지로 독립 검증될 때만 그 잔여 바이트 하나를 제거합니다. 정상 헤더·데이터의 분할 수신은 보존하며, 여러 바이트 잔여물·불완전하거나 손상된 새 읽기·시간이 지난 조각은 계속 오류로 처리합니다. 임의 위치를 검색하지 않으며 Ethernet/IP/UDP 검증도 유지합니다. 이 바이트가 기기나 USB 계층의 어디에서 생기는지는 아직 확인되지 않았습니다. 실제 끊김 개선 여부는 사용자 Mac 재시험이 필요합니다.

문제 정보 복사에 복구 횟수·제거한 경계 바이트 수와 비활성 `GH-RNDIS-RECOVERED` 기록이 추가됩니다. 실패·복구 헤더의 숫자 필드, 제한된 미완성 접두부 숫자값, USB 읽기 길이·번호와 빌드 식별값만 포함하며 원본 바이트 덤프·영상·MAC·일련번호·개인 경로는 기록하지 않습니다. 기존 HTTPS 인증서 및 USB 분할 수신 수정은 유지됩니다.

Mac 설치본에 HTTPS 인증서 신뢰 저장소를 포함하고 업데이트 확인·설치 파일 다운로드에 명시적으로 적용했습니다. 인증서 체인과 서버 이름 검증은 유지되며 신뢰하지 않는 인증서는 계속 거부합니다. 기존 설치본에서 `CERTIFICATE_VERIFY_FAILED`가 발생하면 브라우저로 이번 pkg를 내려받아 한 번 수동 설치하세요. 내려받은 `.ghupdate`도 프로그램의 업데이트 패키지 선택 기능에서 검증해 설치할 수 있습니다. 이전 네이티브 패키지 검사는 HTTPS 연결을 검사하지 않았으며 이번에는 패키징된 앱에서 실제 GitHub의 서명된 업데이트 정보와 설치 파일 다운로드까지 확인합니다.

USB 읽기가 RNDIS 헤더나 데이터 중간에서 나뉠 때 정상 조각을 오류로 처리해 재연결하던 문제를 수정했습니다. 완성된 패킷은 즉시 처리하고 나머지는 크기·시간이 제한된 버퍼에 보관합니다. 잘못된 길이·구조와 실제 영상 손상은 계속 오류로 처리합니다. 문제 정보에는 안전한 오류 종류·작업 단계·분할 수신 수치가 추가되며 같은 초의 반복 오류는 횟수로 묶입니다.

macOS 15.6 이상인 호환 Apple Silicon Mac을 대상으로 하는 공통 arm64 설치 파일입니다. M1·M2·M3·M4 및 이후 호환 M 시리즈에 사용하며 모델별 CPU 전용 빌드가 아닙니다. Intel Mac, Windows ARM, Linux는 이 릴리스에 포함되지 않습니다.

**이번 수정으로 실제 Mac의 끊김이 해결됐는지는 사용자 재확인이 필요합니다.** 이전 버전에서 Mac 영상 수신과 반복 끊김이 보고됐습니다. 분할 읽기 처리 결함은 자동 테스트에서 재현·수정했지만 그것이 보고된 모든 끊김의 원인이라는 뜻은 아닙니다. 네이티브 CI는 의존성·H.264 디코딩·이미지 처리·Cocoa UI·클립보드·분할 패킷 처리·ad-hoc 서명 무결성을 확인합니다. USB 백엔드는 드라이버 강제 분리·장치 자동 초기화·시스템 네트워크 설정 변경을 하지 않습니다.

`Goggles-HDMI-macOS-arm64-1.2.5.pkg`를 다운로드하면 응용 프로그램 폴더에 Goggles HDMI가 설치됩니다. 앱에는 임시 ad-hoc 서명이 있지만 설치 pkg에는 Apple Developer ID 서명이 없으며 Apple 공증도 없습니다. Gatekeeper가 설치나 실행을 제한할 수 있습니다. macOS가 제공하는 설치·실행 확인 화면을 따르세요. 프로그램은 시스템 보안 기능을 끄도록 요구하지 않습니다. 정식 Developer ID 서명·공증을 위한 배포자 인증서는 이번 빌드에 사용되지 않았습니다.

USB 데이터 케이블로 Goggles 3를 직접 연결하세요. 고글에서 OTG 컴퓨터 유선 연결과 라이브뷰 공유를 켜고 DJI Assistant 등 다른 장치 프로그램은 종료하세요. 앱의 USB 설정에서 안내를 확인하고 연결하세요. USB 장치·인터페이스·RNDIS·ARP·영상 패킷·디코딩 단계가 구분됩니다. 권한·사용 중 오류가 나면 오류 코드를 표시하며 장치를 강제로 가져오지 않습니다.

외부 화면을 확장 모드로 연결하고 출력 화면으로 선택하세요. 앱 활성 상태에서 Cmd+D / Ctrl+D / Escape 또는 제어창의 출력 종료 버튼으로 출력을 해제합니다. 이 키는 macOS 전역 단축키가 아닙니다. 화면 잠자기 방지는 출력 중에만 적용됩니다. 워터마크 인증 저장은 macOS 키체인을 사용하며 저장이 거부되면 현재 실행 중에만 인증을 유지합니다.

Windows는 기존 stable/latest 업데이트 경로를 유지하며 1.1.0 릴리스도 보관합니다. Mac은 별도의 서명된 arm64 업데이트 경로를 사용하고 Windows 최신 업데이트가 되지 않습니다. 기존 Mac 1.2.0의 업데이트 채널과도 호환됩니다. 검증된 Mac 업데이트는 Apple 설치 프로그램을 열며 운영체제 확인을 거칩니다.

상단의 **문제 정보 복사**를 누른 뒤 지원 채팅에 붙여넣으세요. 현재 단계와 GH-* 오류 코드, 앱·운영체제 정보, 수신 수치와 최근 오류가 복사됩니다. 연결·진단 전에도 동작하며 버튼을 눌러 장치를 재검사하거나 인터넷으로 보내지 않습니다. 비밀번호, 일련번호, 개인 파일 경로, 임의 URL, 원본 로그와 영상은 제외합니다.

실기기에서 남은 확인: USB 인식 → 인터페이스 확보 → RNDIS → ARP → DJI 패킷 → 디코딩 해상도 → 외부 출력; 재연결·종료 후 재실행; 키체인 인증 저장; 색보정·안정화; 실제 화면 픽셀 모드; 출력 해제와 10분 라이브뷰 유지. 입력 프레임률과 출력 화면 주사율은 구분해서 확인해야 합니다.
